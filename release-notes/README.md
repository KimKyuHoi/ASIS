# release-notes — 사용자에게 보이는 릴리스 노트

이 폴더의 파일은 두 곳에 그대로 쓰인다.

1. **앱의 "변경 이력" 창** — main 번들에 포함돼(`src/main/patch-notes/releaseNotes.ts`)
   네트워크 없이 현재 UI 언어로 표시된다. 새 버전을 처음 실행하면 업데이트 안내 창이 한 번 뜨고,
   [공지 보기] 를 누르면 이 노트로 창이 열린다.
2. **GitHub 릴리스 본문** — `.github/workflows/release.yml` 이 태그 빌드 때 이 파일로 본문을 쓴다.
   파일이 없을 때만 changelogen 자동 생성(커밋 목록)으로 대신한다.

## 파일 이름

```
release-notes/<version>.ko.md
release-notes/<version>.en.md
```

- `<version>` 은 `v` 없는 semver — 태그 `v0.8.0` → `0.8.0.ko.md`.
- **ko·en 둘 다 쓴다.** 한쪽만 있으면 앱이 그 버전을 "로컬 노트 없음"으로 보고 GitHub 본문으로 대신한다.
- 노트가 없는 버전(예: 사소한 패치)은 새 버전 안내 창이 뜨지 않는다.

## 형식

간단한 마크다운만 쓴다. 앱은 의존성 없는 작은 파서(`src/renderer/patch-history/lib/markdown.ts`)로
아래 문법만 렌더한다.

- 제목: `## 새 기능`, `## 개선`, `## 고친 점`, `## 제거` (en: `## New`, `## Improved`, `## Fixed`, `## Removed`)
- 항목: `- ` 로 시작하는 한 줄. 들여쓰기 하위 목록은 쓰지 않는다.
- 인라인: `**굵게**`, `` `코드` ``, `[링크](https://…)` (https 링크만 열린다)
- 버전 제목(`# v0.8.0`)은 쓰지 않는다 — 창과 GitHub 가 버전·날짜를 따로 보여 준다.

```md
## 새 기능

- GIF 녹화가 끝나면 바로 클립보드에 복사할 수 있습니다.

## 고친 점

- 에디터 창을 제목 표시줄로 끌어 옮길 수 있습니다.
```

## 문장 규칙

- **사용자 관점**으로 쓴다. "무엇을 할 수 있게 됐는지"가 먼저, 구현(파일·클래스·IPC)은 쓰지 않는다.
  - ✅ "스크롤 캡처 중 직접 스크롤해서 원하는 만큼만 담을 수 있습니다."
  - ❌ "scrollCapture 에 manual 모드 추가"
- 메뉴·버튼 이름은 앱 UI 문구와 같게 쓴다(ko 는 ko UI, en 은 en UI 문구).
- ko 는 존댓말 서술(`~합니다`, `~할 수 있습니다`), en 은 짧은 현재형 문장.
- 한 항목은 한 문장. 길어지면 두 항목으로 나눈다.
- 외부 기여 PR 은 문장 끝에 링크로 감사 표시를 해도 된다.
